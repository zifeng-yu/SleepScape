# LLM睡眠分析方案

更新：2026-11-17。**方案、Prompt及合同已建立，模型层、分析服务与看板栏目尚未开发。** 用户将提供URL/Key；本轮没有调用模型或发送真实健康数据。技术连接见[模型层](models.md)，合同和完整性规则唯一维护在[数据契约](../data-contract.md#睡眠分析合同待实现)。

## 用户确认的流程

每天09:00按配置回查Garmin API，结合硬件已上传/补传记录，更新看板及缺项清单。**双源必需数据齐全才首次分析，每晚最多发布一份成功报告。** 不先输出缺少环境数据的报告，不生成partial报告，不对已发布报告自动修订。

`SLEEPSCAPE_GARMIN_LOOKBACK_DAYS=7`是计划新增配置，含当日睡眠来源日D−6…D；用户描述的“−7”映射为正整数7。范围1—31。尚未齐全的夜晚在窗口内每天复查，越出窗口则`expired_unanalyzed`，保留缺项和原始数据；显式扩大窗口/指定补采后才重新评估。硬件未通电、传感器失败或缓存已丢的过去数据不能靠API补造。

报告发布前，若生成过程中源数据变化，候选结果作废并记录尝试，等下次日常任务重新检查；发布后源数据有变化，保留原报告及其输入快照，显示`source_changed`，不再自动调用。Prompt/模型配置升级也不绕过每晚唯一报告约束。数据事实可以补齐或被Garmin修正，报告保持生成时快照，这是两个独立层次。

## 需要得出的结论

| 栏目 | 可输出内容 | 证据限制 |
| --- | --- | --- |
| 本晚概况 | 睡眠时长、窗口和可用累计阶段；与个人历史相比的变化 | 数值与差值由程序算好；没有分期区间不描述几点进入深睡 |
| 身体信号 | 夜间平均心率、HRV相对个人基线的变化 | 不将HRV单项变化等同恢复能力、疾病或训练许可 |
| 前日背景 | 昨日运动负荷、压力、可用活动时间及持续时长 | 负荷沿用既有全部运动口径，不由模型重新计算或假定无活动=休息 |
| 环境观察 | 温湿度水平/波动、光照分布、相对声音强度/事件摘要 | 声音为dBFS，事件不是声源/鼾声识别；合并包络不是持续噪声 |
| 待验证线索与下一步 | 最多3条有依据的可能关联、替代解释，以及低风险的记录/环境观察建议 | 只作观察假设，不宣称最大影响因素、因果比例、诊断、用药或强度训练处方 |

“结论”允许是“现有资料无法确定影响因素”。首版不强行计算相关系数、因果权重或新增综合睡眠分数。优先解释明确观测，再给有限假设；假设不按影响大小排序。咖啡因、酒精、疾病/药物、主观睡感等未记录因素必须列为未知，不能填无。

采用这种边界是因为可穿戴估计及环境观测不能直接升级为诊断依据；[AASM技术评估](https://pmc.ncbi.nlm.nih.gov/articles/PMC8636367/)讨论了消费级测量及验证边界。该资料用于约束产品用途，不表示已验证本手表或本项目的准确度。

## 输入准备

`domain/sleep_features.py`纯计算，`services/sleep_analysis.py`组织一致快照；不将完整数据库、原始API JSON、日志或图表截图发送给模型。

1. 以API的睡眠来源日/真实起止定位主睡眠，不把自然日00:00切成两晚；今日“暂定”标记本身不阻塞，睡眠未结束或必需项不足才阻塞。
2. 先执行数据契约中的严格双源门槛，形成可复查缺项。满足门槛才建立发送用输入。
3. 睡眠、平均心率、HRV、前日负荷/压力、可用阶段累计等做白名单事实；包含单位、来源、日期、质量和稳定证据ID。差值、分母、覆盖率由程序计算，模型不重新推算。
4. 个人睡眠/HRV/心率基线用本晚之前30个来源日，有效值逐指标计数；至少7个有效夜晚才提供对应比较，未满30明确样本数。运动负荷比较严格复用`domain/training_load.py`：目标D−1，基线D−31…D−2，30个有效完整自然日不足则不输出百分比。两种分母不可混用。
5. 环境只发整夜统计、分段变化及有限事件摘要；声能均值按有效时长在能量域聚合，不能算dB算术平均。首版报告门槛要求整晚同一设备/配置/摆位，改变时阻塞分析；看板仍分段展示，不能跨断点拼成可比较声音基线。
6. 可选15分钟环境摘要用于解释整夜变化，最多96段；保留每段有效覆盖和配置段。超出24KiB输入预算时先移除可选分段，再移除非必需背景；不能丢核心事实/缺项/限制后冒充完整。仍超限则`blocked_input_budget`，不调用。
7. 不提供姓名、账号、GPS、设备序列号、Wi-Fi、URL、Key、原始活动标题。来源文本只作为数据，不作为指令；首版不接自由文本日记或外部网页到Prompt。

初期API未给连续分期；绝对时间误差也未独立校准。允许展示有锚点的估计UTC，但不让模型从未知误差时间或分钟摘要推断秒级先后/噪声导致觉醒。完整性通过仅表示满足采集合同，不表示医学准确或各指标互相吻合。

## Prompt与输出

唯一system Prompt为[文本文件](../prompts/sleep-analysis-system.txt)，发送时将输出Schema和白名单JSON作为独立user消息数据，不插入可执行指令。Prompt版本/文件SHA-256与每次尝试一起保存。输入/输出的机器结构为[合同Schema](../contracts/sleep-analysis.schema.json)，[合成样例](../contracts/sleep-analysis.example.json)用于离线核验，不能当作用户真实结论。

输出包含`summary`、`observations`、`hypotheses`、`actions`、`limitations`。每项事实或假设引用输入中存在的证据ID；限制引用程序给出的限制代码。结构外字段、未知引用、缺限制、医学诊断/确定因果、无来源数字、截断输出均不能直接发布。

程序完成Schema、引用、数值/单位、类别和数量上限校验；不把JSON正确等同自然语言结论正确。事实数值在页面从证据卡渲染，模型文本主要解释方向和限制；轻量规则无法证明所有语义推断，真实报告首次验收需人工对照数据。假设证据级别首版只允许`limited`；观测或比较可用`moderate`，不能输出精确概率或“高可信因果”。

## 执行、预算与唯一发布

未来`services/daily.py`统一编排：09:00 Garmin sync（有限重试）→刷新受影响环境时间索引→按配置窗口检查缺项→对无成功报告且ready的夜晚构造输入→有限模型调用→短事务发布。当前timer仍只执行garmin-sync，不能把此流程标成已自动运行。

每晚有唯一`night_date`报告约束；同日重复任务/服务重启不能重复发布，同一已占位尝试不重复扣预算，新物理请求必须另计次数。输入hash按数据契约覆盖实际发送的事实、质量、映射后时间和完整性策略版本；排除读取截止时间及is_provisional，不加入API请求ID。报告另存Prompt hash、model_ref、模型配置/能力版本与时间映射版本；发布时核对这些版本，不能把内部版本号变化本身解释成源数据改变。Key轮换不改变业务身份。

默认单并发；每自然日最多分析2个待生成夜晚、最多4个物理模型请求（包含重试/显式连接检查）。优先当日ready夜晚，其余名额处理窗口内最早ready夜晚，避免旧夜晚饥饿。每个输入每天最多2次尝试（初次+最多1次重试），跨日累计最多6次，达到上限标`blocked_attempts`，显式排障后才解除；进程重启不重置计数。一次通常1个请求，没有为了达到预算而额外调用。

模型单次硬截止180秒，含思考的输出上限4096 token，响应上限256KiB；最多4次约12分钟外呼加少量退避是日任务资源预算，不是实时完成保证。计数/占位在请求前持久化；超时结果未知也计尝试。模型不可用不回滚已保存数据，不阻断硬件接收与看板。

网络超时/指定5xx可在剩余预算内重试一次；429尊重Retry-After，超过本轮剩余时限就延后；401/403/模型不存在/能力不支持停止模型任务。结构错误可一次纠错重试，和网络重试共用额度，不能各加两次。服务返回的错误文本不作为下一条system指令。

模型外呼之前关闭SQLite只读事务；外呼结束后重新核对ready、输入hash、私有source_fingerprint及每晚报告唯一性，原子保存。私有来源指纹在不ready时也可计算，覆盖来源身份及缺失/无效状态，详见数据契约；不能仅靠可发送摘要识别来源变化。若数据变化则状态`discarded_input_changed`、候选不展示，次日再检查；若已有成功报告则丢弃重复候选。报告保存来源指纹，发布后由它识别变化，永不由定时任务覆盖。

仅保存最终答案、必要元数据及私有输入证据，不保存/展示思维链。真实价格未知时显示usage及“费用未知”；默认预算是次数/字节/token上限，不承诺固定月费。

## 数据与界面

待增独立表：`analysis_schema`、`analysis_inputs`（压缩JSON/hash）、`analysis_attempts`（占位/预算/结果状态）、`sleep_analysis_reports`（night唯一）、`analysis_readiness`（缺项/检查状态）。原始Garmin/环境表不被报告覆盖。迁移必须显式执行、先备份、幂等且可恢复；GET不建表或写库。备份验证覆盖所有新表。

只读`GET /api/v1/nights/{D}/analysis`：返回状态、缺项、已存报告和白名单证据卡；参数沿用已有日期/访问保护。不返回Prompt、完整输入、Key、URL或原始模型响应。刷新/选日期不触发模型或采集，不新开浏览器写入入口；人工排障/补采采用CLI。

夜晚页新增“LLM睡眠分析”栏目，**先展示明确状态而非虚构示例结论**：缺配置、缺Garmin、缺环境、超出回查窗口、待分析、分析中、失败/预算限制、已生成。缺项显示具体日期/通道/缺失分钟数/失败原因/最近检查及下次计划。成功页显示结论类型、证据、局限、生成时间及依据快照；source_changed独立提示“当前数据与报告生成时不同，原报告保留”。

历史页增加分析状态；数据状态页增加模型配置就绪、调用结果/预算/usage，不显示秘密。可选指标缺失同样显示，但明确“非阻塞项”；核心缺项与传感器不支持不能混为一谈。

失败原始响应最多保留30天且总量限额；没有成功报告引用的废弃输入可在审计保留期后清理。成功报告及其依赖快照至少保留一年；模型记录与原始观测一样是私有证据，不作为冗余程序删除。

## 实施与验收

先建models层、合同/Prompt和只读栏目状态；随后完善环境UTC查询和双源完整性，最后接入真实模型生成。**可以先开发栏目，但没有齐全数据时不能提前产出结论。** 所有待建文件与顺序见[补齐计划](completion.md)。

必须覆盖：缺任一核心字段零外呼、缺一整分钟/单通道零外呼、可选缺失不阻塞、D日缺D+1补齐后只发一次、源数据在生成中变化不发布、发布后变化仅提示、同夜重入唯一发布、限流/超时/截断/错引用/提示注入、程序重启预算不重置、模型慢请求期间硬件写入仍可用。所有自动测试只用合成数据；真实模型质量和真实双源数据仍待凭据与持续采集。
