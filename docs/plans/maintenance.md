# 自动维护与容量保障方案

更新：2026-11-17。**方案待实现。** 当前已有在线备份与临时恢复检查；自动备份、保留策略、离机复制、磁盘水位保护仍未实现。云服务器安装不在本轮执行范围。

## 分层与文件

| 待建/修改位置 | 职责 |
| --- | --- |
| `domain/retention.py` | 只根据受控清单、时间和预算计算保留/删除候选，不访问磁盘 |
| `domain/maintenance.py` | 纯磁盘水位和任务许可规则 |
| `storage/usage.py` | 读取磁盘、数据库/WAL/SHM、受控备份和私有分析证据大小 |
| `storage/backup_manifest.py` | 受控备份清单：创建/验证时间、大小、哈希、远端确认、状态 |
| `services/maintenance.py` | 备份、验证、导出、保留决策及执行；短事务更新维护状态 |
| `adapters/backup_export.py` | 向用户指定的路径/SSH目标传输，不决定删除策略；加密/SSH工具须固定允许参数 |
| `services/backup.py` | 扩展恢复校验至派生索引及LLM输入、attempt、报告表 |
| `cli.py`、`deploy/maintenance.service/.timer` | 显式维护命令及每日04:00上海时间模板（均待编写） |
| `services/views.py`与状态页 | 最近成功备份、离机状态、容量预警、维护失败；不暴露文件路径和凭据 |

Garmin的`.collection.lock`当前只约束Garmin采集，不扩成全应用锁。维护使用独立任务锁；LLM用独立租约。外部传输/推理不持数据库锁，SQLite事务尽量短；WAL在线备份按既有分页方式执行。并发忙超时可重试，不把收到请求视为已提交。

## 备份执行与保留

1. 检查源库、备份目标、空闲空间和清单；路径限定在配置目录，拒绝符号链接和未知文件。首次迁移先登记现有可验证备份，不能仅按UUID文件名判断先后。
2. 创建新的独立SQLite副本，包含已提交WAL；验证完整性、外键、所有事实表及新增LLM表的数量、JSON/内容哈希、引用关系。派生索引必须可验证或明确可重建。
3. 验证成功后原子发布清单。备份创建/校验失败时保留旧副本，不启动删除。
4. 用户指定离机目的地后，加密传输并核验目标摘要；本机清单记录确认，不在普通日志输出连接秘密。目的地未提供时为`offsite_not_configured`，可继续本地开发与备份，但不能标离机保护已完成。
5. 按份数与总量双限制清理**程序管理的旧备份**，默认目标最多3份；磁盘预算容不下3份时不能伪称已留3份。始终保留最新一个已验证本地副本。仅有一个有效本地副本且空间不足创建新副本时，不先删它赌下一次成功；报空间不足，等待安全转移或扩盘。

离机保留也设置份数/总量上限，默认目标7份日备份、4份周备份（同一文件引用去重），以实际目标空间为准。尚未提供目的地，不承诺此保留量可行。原始观测不是备份清理对象；不删环境/健康事实来伪装容量达标。恢复操作保持人工显式执行并有恢复演练，不新增无人值守覆盖生产库的“自动恢复”。

LLM输入快照和有效报告是私有证据：采用内容哈希去重与压缩，每晚最多一个成功报告，保留该报告及所依赖快照。失败/未发布候选的归档规则见[LLM方案](llm.md)，删除先核对没有成功报告仍引用。例行清理不接触密钥、手工文件、正在生成的文件和原始事实。

## 容量规则

以下为待目标机核验的工程默认值，不是已实现或已经满足的服务保证。系统总盘和实际数据分区分别检查，按更严重状态处理。

| 水位 | 行为 |
| --- | --- |
| 空闲≥25% | 正常，仍按备份临时空间需求预检 |
| 空闲<25% | 状态页预警，记录DB/WAL/备份/模型证据增长，优先处理已过保留期的受控产物 |
| 空闲<15%或<2GiB | 暂停新的LLM外呼和大备份任务；已运行任务有界结束。读取、正常小批接收优先保留 |
| 空闲<5%或<512MiB，或实际磁盘写失败 | 进入临界状态：环境接收返回503及可重试提示、不ACK；Garmin暂停新写批次并记录安全状态；保留读取。维护状态无法写库时仅产生有界静态错误 |

备份额外要求可容纳新完整副本、WAL增长与余量；大于阈值不代表一定允许创建。禁止手工删除WAL/SHM，不自动VACUUM占满临时空间。设备缓存有限，临界状态持续超过缓存能力仍可能丢失，不能保证无限期保数据。

系统日志限额、轮转与服务内存限制用systemd/journald/Caddy配置实现，不新建日志平台。程序日志只保存错误码和必要元数据，不记录PCM、健康正文、Prompt正文或Key。库内审计需要有界且可追踪，不因“清日志”删除观测来源证据。

## 一年容量预算与验证

既有约1.3GB/年的环境SQLite估计不包含Garmin、模型输入/输出/attempt、派生UTC索引、备份、WAL、系统依赖。LLM按最多4个物理请求/日、每次响应256KiB及输入24KiB计算，未压缩请求/响应上界约400MiB/年量级；这只是保守字节预算，表/索引/修订和备份另算，不能推断实际模型账单。

部署前以一年合成数据测查询计划、DB和索引增长；部署后第7和第30天复核实际日增量。公式为：系统占用＋一年事实/派生/LLM证据预测＋有效备份＋WAL/日志临时空间＋至少25%余量。超过20GB时比较保留策略及扩盘，不先假定CPU/内存升级能解决磁盘。

## 验收清单

- 新备份失败、校验失败、远端失败：旧有效副本不被删除；清单损坏/未知路径/符号链接拒绝执行。
- 受控清理中断可重跑；份数和字节预算兼顾，永不删唯一有效本地副本或正在生成的备份。
- 恢复后Garmin、环境、LLM快照/报告/尝试与输入指纹一致；派生UTC索引可重建且不改事实。
- 四档空间边界及实际ENOSPC；临界接收失败不ACK，设备可补传；告警不能称为实时采样失败。
- Garmin、硬件入库、备份、LLM快照并行；外呼无数据库锁，忙超时有界，WAL不无限增长。
- 合成年度容量测试和目标机2核2GB性能分别记录。离机目标、实际云资源、长期运行数据未提供时明确待验。
