# 自动维护与容量保障方案

更新：2026-11-20。云端每天 04:00 执行同机成套备份与恢复核验。维护覆盖受控保留、容量保护、路径或 SSH 导出及看板状态。真实离机目标待配置，长期运行与资源增长待验收。参见[云端运行证据](../verification.md#云端三晚运行核验2026-11-20)。

## 分层与入口

| 位置 | 当前职责 |
| --- | --- |
| `domain/maintenance.py`、`domain/retention.py` | 纯磁盘水位、操作许可、份数/日期/容量保留决策 |
| `storage/usage.py` | 系统盘和数据盘只读statvfs、固定文件大小、共享容量准入及磁盘满错误识别 |
| `storage/backup_manifest.py` | 私有维护账本、受控清单、严格结构、原子写入、独立进程锁 |
| `services/backup.py` | 保留原手动SQLite备份/恢复检查，并接入容量预检 |
| `services/backup_bundle.py` | SQLite与模型/每日运行/冷却状态的一致快照、文件摘要和恢复核验 |
| `services/maintenance.py` | 同日幂等、显式失败重试、备份→导出→保留、崩溃恢复、只读状态 |
| `adapters/backup_export.py`、`backup_export_worker.py` | 路径与严格SSH传输、目标核验、不可变发布、受控目标保留；有界子进程/流式复制 |
| CLI、`deploy/maintenance.service`/`.timer` | `maintenance-run [--plan-only或--retry]`、`maintenance-status`、`maintenance-restore-check ID`；云端04:00 Asia/Shanghai定时器已启用 |
| `services/views.py`、`web/static/maintenance.js` | 独立维护卡；任务、备份、目标、磁盘状态白名单，无路径或凭据 |

维护使用独立`.maintenance.lock`。取得成套快照时短暂获取现有Garmin及模型进程锁；正在采集/调用模型则维护明确报忙，不打断任务。SQLite一致读快照仍允许环境独立WAL摄取；复制后释放采集/模型锁，再做完整校验、恢复检查和网络导出。维护锁不变成全应用写锁。任务20分钟systemd上限和导出总超时用于终止异常；目标机首次恢复核验已通过，长期耗时与资源仍须测量。

## 成套备份与恢复边界

受控备份目录为`data/backups/managed/<ID>/`：`sleepscape.sqlite3`、已有的`model-runtime.json`、`daily-runtime.json`、`collection-cooldown.json`及`manifest.json`。清单记录文件存在性、大小、SHA-256、创建时间、各表计数；不存在的运行账本明确记录为不存在，不伪造新状态。模型预算/日任务状态须通过原结构校验，日任务run_id须对应同批SQLite审计。

创建时预检复制与临时恢复空间，在线备份包含已提交WAL。核对完整性/外键/raw哈希与JSON、环境记录/可选UTC索引、存在的晨起睡感、完整性、逐夜报告及修订、7 日复盘及失败归档的结构、载荷摘要和引用。缺省可选表的有效备份可继续核验，部分存在或版本异常时拒绝。临时恢复核对表数和账本，全部成功才发布，不覆盖生产库。

`maintenance-restore-check`只在临时目录恢复、校验，结束清理，不替换生产文件。维护清单`maintenance-state.json`独立管理所有包，**不在单个包内**；迁移整个运行环境时与备份目录一起私下保留。凭据、`.env`不写入备份包，仍需私下迁移。`db-backup` 是单库备份入口，成套备份包含配套运行账本。

真正恢复由人工停服务后显式执行，采用同一个已核验包内的库与账本。不能把较新completed账本配旧数据库，也不能删除账本绕过预算或Retry-After。备份后的调用无法从旧快照推断：若有更新的模型/限流证据，须保留更严格的额度和冷却期；无法确认当日已用额度时，恢复当天暂停新的模型调用，待下一个上海自然日再启用。禁止自动恢复覆盖运行库，禁止手工删除仍在使用的WAL/SHM。

## 保留、导出与失败恢复

- 本地默认最多3份受控包、总量4GiB，两者共同约束。始终保留最新已核验包；若单包已超预算，保留它并显示超预算，不宣称满足3份目标。新包/恢复核验失败时，不先删旧包腾空间。
- 每轮显式维护有界登记并核验旧的手动SQLite备份，标明其数量/体积；它们不含配套账本、处于自动清理之外。未知文件、原始事实、凭据、任意同名文件和符号链接不作为删除候选。大量历史手动备份需要另行核对，不能假定4GiB已覆盖它们。
- 清单损坏或权限不安全时拒绝执行，不清空重建。删除前校验已登记包，逐项持久记录deleting并核对剩余文件摘要，重入可继续；最新有效包始终保留。新包未验证或已配置的导出失败时，不开始本地旧包清理。
- 同一上海日完成任务默认跳过；未完成可显式`--retry`。已有成功包的失败重试可复用原快照，再做导出/清理，不假装重试时刻产生了新快照。长期审计保留在数据中，维护运行摘要有界。
- 导出默认disabled并显示`offsite_not_configured`。path模式要求已存在的私有绝对目录，缺少挂载时不自动创建目标；它只证明复制成功，不能自动确认是否另一台机器或已加密。
- SSH模式要求显式目标、专用身份、已核验known_hosts、远端Python3及私有目标目录；严格主机核验、非交互、无代理转发，超时有界。只确认加密传输与目标摘要，不推断磁盘静态加密。真实远端未配置，本轮只做合成传输与故障验证。
- 目标默认保留最近7个有备份的日期及4个ISO周的最新备份，同包去重，总量16GiB；同样保留最后有效包并提示单包超预算。采用独立受控命名空间/清单、逐文件摘要、原子发布和中断恢复，只清理已登记文件。失败不报告已离机成功。

所有元数据目录700、文件600。数据库复制/文件哈希按块处理，导出以有界工作进程进行；不用整库读进内存，不引入Redis、Celery、MQTT或新常驻服务。状态GET只读有界账本和磁盘统计，不扫描完整备份、不做恢复核验、不联网。

## 容量规则与写入保护

系统盘和数据盘分别检查，采用更严重水位；状态不可读取时拒绝新增写入/模型/备份，仍允许现有只读页面。

| 水位 | 已实现行为 |
| --- | --- |
| 空闲≥25% | 正常；备份仍须计算额外复制/恢复所需空间 |
| 空闲<25% | 显示预警，保留正常采集能力 |
| 空闲<15%或<2GiB | 暂停新的模型请求与大备份；模型在额度预留之前拒绝，正常小批接收继续 |
| 空闲<5%或<512MiB | 环境接收503、Retry-After=60且不ACK；Garmin在联网/分页及保存前检查，停止新增写批次；读取继续 |
| 实际ENOSPC、EDQUOT或SQLITE_FULL | 当前写入失败、事务不确认；设备可按失败响应重传，错误输出固定码，不泄露数据库正文 |

备份预留后必须仍有至少15%和2GiB空闲；预估考虑源库/WAL、成套文件及临时恢复开销。未知空间不按充足处理，不先删除唯一有效副本，不自动VACUUM。并发写入仍可能在预检后耗尽空间，因此真实写失败的回滚和无ACK也是必要保护。介质损坏和无限期服务器故障无法由有限设备队列兜底。

日志使用systemd/journald与Caddy的现有能力；新增专用服务器的可选journald限额示例，不自动修改宿主全局配置。Web保持关闭访问日志，普通错误仅固定类型/代码；不得打印PCM、健康正文、模型Prompt或凭据。日志示例及目标机核验见[运行手册](../operations.md#自动维护与离机配置)。

## 一年容量预算与验证

既有约1.3GB/年的环境SQLite外推不包含P2 UTC派生索引、Garmin、模型输入/输出/attempt、备份、WAL、系统依赖。P2已有年度分钟数据索引实测，场景不包含全年声音事件和接收审计，结果统一见[核验报告](../verification.md)；两种测试不能相加或互相替代为全年总量。模型请求预算见数据契约。容量按实际持久化的输入、成功报告、修订、尝试及备份增长验收；单次响应上限不能直接用作每次落盘大小。

部署前以一年合成数据测查询计划、DB和索引增长；部署后第7和第30天复核实际日增量。公式为：系统占用＋一年事实/派生/LLM证据预测＋有效备份＋WAL/日志临时空间＋至少25%余量。超过20GB时比较保留策略及扩盘，不先假定CPU/内存升级能解决磁盘。

## 验收与外部条件

回归覆盖备份/恢复/导出失败、状态损坏、空间边界和真实模拟写满、只读副作用、同日重入、删除中断、受控/未知文件隔离、模型与每日账本一致性、网络等待不占数据库事务及看板失败隔离。具体通过计数只在[核验报告](../verification.md)维护。

运行与恢复证据见[核验报告](../verification.md)。当前离机导出为 `disabled`，启用真实目标后需在目标侧核对主机身份、传输完整性、访问权限、存储加密及离机恢复。长期资源检查及验收顺序见[建设计划](completion.md)。
