# 看板展示方案

更新：2026-11-25。夜晚详情、晨起睡感、7/30 日历史、7 日概览与总结均已部署。详情先显示已发布解读的概况，随后加载完整报告、证据和当前完整性，历史按截止日读取复盘。交互与线上证据见[核验报告](../verification.md)。
字段、负荷公式、缺失状态和JSON数据形状以[数据契约](../data-contract.md)为唯一依据。

夜晚详情依次展示核心四卡、本晚睡眠解读、睡眠窗口与阶段累计、补充指标、时间轴和关联记录。报告默认展示概况、个人比较、可能解释和后续观察；解读限制、证据和完整性检查明细按需展开。显式重读后详情与历史取同一份当前报告。

## 晨起睡感

夜晚详情头部，在现有日期栏旁放一组小按钮：**晨起睡感　[较差]　[一般]　[较好]**。窄屏可在日期栏下换行，位于核心卡片及空状态之前。三个按钮始终指向页面正在显示的醒来日期；翻到以往日期即可补填或修改。沿用日期控件及展示范围，无需另外选日、区分补填模式或等待每日采集。

首次进入时读取该日睡感，未填则三项均未选。点击即保存，成功后高亮选中项；点击另一项即可修改。按钮可键盘操作，以选中态向读屏软件传达结果。保存中防重复提交，失败提示并允许重试；读取失败显示“读取失败”，与未填区分。切日或刷新要按日期重新读取，晚到的读写响应不能覆盖新日期的按钮状态。

该控件独立于夜晚主体请求挂载。两源均无、仅环境、仅 Garmin 以及两源齐全时均可填写。只把手工输入送往独立睡感接口。分层职责见[架构](../architecture.md#晨起睡感的分层设计)，存储与读写语义见[数据契约](../data-contract.md#晨起睡感记录)。

## 7 日睡眠复盘

在现有历史页回答「这几晚睡得怎样，哪一晚值得回看」。提供 7 日概览和历史表睡感列，可用现有夜晚详情查训练、环境和报告证据。字段和统计定义见[历史复盘数据契约](../data-contract.md#历史复盘)。

1. **选择范围。** 沿用「近7日／近30日」和 URL 中的截止醒来日期，在历史页提供可直接选择截止日的控件。默认仍沿用当前看板所选日期或最近可见睡眠日，手动选今天可回看只有晨起睡感的今天。日期控件与列表请求遵守 API 支持的日期范围和展示起点，显示裁剪后的实际起止日和日历日数。
2. **查看概览。** 7 日视图在表格上方显示三档睡感及未填计数，以及入睡、醒来、主睡眠时长、夜间平均心率和昨夜 HRV 中位数。每项显示自己的有效夜数；全部缺失、单晚数据、睡感暂不可读取各有提示。移动端概览可换行，单位和分母保持可读。
3. **定位夜晚。** 7 日和 30 日表格均在醒来日期后显示睡感，支持「全部／较差／一般／较好／未填写」筛选。表头继续对现有列排序，筛选只作用于表格，标题显示匹配数与范围总数。无匹配时保留筛选控件并可回到全部。睡感不可读取时停用该筛选并展示所有日期。筛选保存在页面内存，刷新恢复全部，URL 沿用视图、日期和天数。点日期仍进入对应夜晚，补填或改选成功后返回历史页时重新读取视图。

**实现边界。** 复用现有 `GET /api/v1/nights` 和 `DashboardService.nights()`，在列表同一 `DashboardReader` 快照中批量读取本页睡感，复用睡眠来源优先级、已有指标状态和安全白名单。存储层负责有限范围内的按日期读取，领域层计算中位数和计数，服务层组合投影，前端负责展示和筛选。睡感表缺失或不能读取时只降级睡感。使用已有请求中止和切换代次保护日期切换；7/30 日范围各执行一次列表请求。7 日概览另读取一次当前范围的已保存总结；曲线和当夜完整解读在夜晚详情加载。睡感写入口与历史只读入口各自独立。

### 7 日复盘总结

在「近7日」现有概览下放置可展开的「7 日总结」卡，只读展示 09:00 日任务的状态与已保存结果。标题始终显示实际起止日。上次因完整度不足而未生成时，读取页面会重新核验该窗口。仍有不足的日期逐日列出，全部通过时显示「完整度已通过」并提示总结尚未生成。等待当日日任务、核验无法读取、模型失败、已生成各有状态。历史表和中位数始终按实际观测展示，保持独立于报告资格。编辑睡感或补采后保留旧报告与生成时证据，核对到变化时显示「复盘依据已更新」。

卡片通过独立只读接口按所选截止日查询。切日期清空旧范围的卡片状态，丢弃迟到响应。新报告展示模型对目标夜的判断、依据、可能原因与前几晚对照。有存档证据的历史报告可展开原引用。30 日视图沿用历史表和睡感筛选。执行流程见[LLM 方案](llm.md#7-日复盘总结)。

## 页面职责

| 页面 | 展示与操作 |
| --- | --- |
| 夜晚详情 | 日期选择、上一晚/下一晚、睡眠时长/平均心率/昨夜HRV/昨日负荷，四卡独立展开来源及口径；睡眠窗口、阶段累计、分轨时间轴与分类关联记录；模型安全状态、当前双源完整性及阻塞项/质量提示/可选缺项 |
| 历史记录 | 按7/30个自然日显示摘要、质量及分析状态，保留空日，列排序并进入对应夜晚。概览和睡感筛选见[睡眠复盘](#7-日睡眠复盘) |
| 数据状态 | 每日采集计划、最近运行、请求汇总与逐日期睡眠记录状态；自动维护计划、备份核验/保留、磁盘保护与目标副本状态；Garmin资源与存储；环境设备最后接收与已映射采集时间、配置、通道健康和缓存快照、未知/冲突计数；模型配置/核验/错误/usage/次数预算 |

首屏选择允许展示范围内最近有睡眠数据的日期，明确日期及抓取时间；有效数据直接展示，缺失、无效、最近请求失败旧值按实际状态提示，不因日期是今天统一标“待确认”。没有可见睡眠时，选择配置时区今天与展示起始日的较晚者，并显示缺少数据，不能退回被隐藏的旧夜晚。
日期为空时不自动跳过，不把旧夜晚称为今天。页面刷新只查询本地数据与安全状态，不执行Garmin采集或模型调用。
每张核心卡的“来源与口径”独立展开来源字段、来源日、抓取时间、缺失原因及必要分母；展开一张不改变其他卡片的开合状态，布局不把同排卡片一同拉高造成联动错觉。昨日压力/步数与呼吸、评分作为补充。
负荷采用全部运动类型，并关联睡眠日的前一天；列表排序不产生影响因素排名。

### 睡眠日期展示起点

可选配置`SLEEPSCAPE_DASHBOARD_START_DATE`将夜晚入口、日期控件、上一晚/下一晚和历史记录限定到起始睡眠归属日及之后；旧URL进入时夹到允许日期，历史窗不生成起点之前的空日。配置为空则保持全部历史可浏览。实际起点与生效证据见[运行手册](../operations.md)和[核验报告](../verification.md)。

这是睡眠归属日过滤：11月18日睡眠可包含11月17日晚环境，不能从18日零点截掉跨夜读数。旧数据、昨日运动及30日基线照常保留和计算，Garmin回查继续按N日配置运行。独立环境自定义UTC窗口仍允许查询调试数据，因此该设置不是数据删除或安全隔离边界。字段和错误码以[数据契约](../data-contract.md#看板睡眠日期展示边界)为准。

## 睡眠与统一时间轴

睡眠窗口显示入睡、醒来和日期；深睡/浅睡/REM/清醒仅显示累计时长，并标明无分期时间线。
当前API没有分期区间，累计条不对应夜间顺序，不能用累计值生成区间。

图表标题为“身体与环境时间轴”，短说明提示点选读数，完整每分钟环境读数在曲线中查看；数据质量与缺项说明放在图表下方。时间轴默认睡眠起止前后各1小时，心率、HRV、SpO2、Body Battery及四环境指标共用横轴。每轨明确指标名称、单位、数值刻度和网格；上下时间轴都显示日期与时间，跨午夜不只留模糊小时数字。活动、午睡和相对声音摘要作为独立标记，不混成连续数值曲线。
没有可信睡眠窗口时回退前日18:00至当日12:00并明确原因，该查询范围不代表推断出的入睡/醒来。
UTC用于对齐，页面按配置时区显示。图表使用实际观测点，缺口不插值、不解释为醒来或离腕；小时血氧与稀疏Body Battery不扩展为连续分钟读数。

支持的交互：

- 光标联动；Garmin只在容许时间差内匹配实际样本，环境只匹配包含光标的真实分钟窗口，缺口不借邻近值；提示实际观测时间和分钟统计。
- 点选图表可固定详情并滚动查看全部指标，Esc或“取消固定”关闭；手机多轨详情限制在视口内，不遮住后无法访问下部内容。
- 框选、平移、Ctrl/Command加滚轮缩放及恢复整夜；键盘支持缩放、平移、Home恢复。
- 整夜、前一日活动、自定义区间；自定义窗口最多48小时。事件可展开摘要并定位时间轴。
- 图例按指标及均值/峰值类型归并，同指标的多个boot不重复占满图例；开关控制该组对应序列，但各原始来源/启动分段继续独立，不能跨段连线。页面、日期、图例和历史7/30日选择写入URL，刷新及浏览器前后退恢复。缩放范围不承诺跨刷新保存。
- 手机响应式排版；普通滚轮/纵向滚动不因默认缩放交互被劫持。真实移动设备验收状态见核验报告。

显示点数受服务器限制。超限序列按时间桶保留有效min/max及真实时刻，附原始/有效/显示点数和桶宽。
稀疏序列直接返回；显示降采样不改变标准化或raw记录，不在空桶生成点，不删除活动事件。

### 这晚的关联记录

由独立`web/static/events.js`呈现“这晚的关联记录”，以全部、运动、午睡、声音摘要分类并显示各类当前条数；筛选只影响列表，不删除数据。运动包含前一日全天与当前图表窗口内的运动，午睡和声音摘要按当前图表窗口显示，栏目明确列出这两个范围。每条仍可展开来源/时长，并定位到时间轴。

该栏目展示的是额外摘要标记，完整每分钟环境读数在图表中，摘要数不应等于分钟数。声音明显高于背景时可生成摘要；持续声音可能跨分钟拆分，同分钟短片段也可能合并，因此摘要条数不是独立响声数、声源数或觉醒次数。“较响累计”表示摘要内符合检测条件的时长，不代表整个起止包络一直有响声。已发布且仍有效的片段提供播放、暂停和回听模式，点击播放后才请求音频。每段默认原声。选择“减弱低频”时，浏览器用 80 Hz 二阶 Butterworth 高通处理播放输出。同一音频可在原位置切换模式，暂停时选好模式可从原位置继续。浏览器缺少 Web Audio 时仍可播放原声。旧固件的摘要仅有统计值。看板不自动识别打鼾、说话或觉醒。

条数随当前窗口、实际检测与有效采样变化，不固定为某个夜晚的观测数；预热、音频缺口或截断都可能影响可见数量。后端声音事件展示上限及截断字段只在数据契约维护，不能把触顶后的条数解释为整夜总数。仅按需解释通道/检测覆盖，不用大量实现字段替代日常说明。

## 只读接口边界

`services.views`及`services.analysis_views`通过只读查询和安全状态生成字段白名单，不返回完整raw、owner、GPS、凭据、私有模型URL或文件绝对路径。

| 路由 | 查询限制 |
| --- | --- |
| `GET /api/v1/metrics` | 唯一指标注册表，稳定ID、名称/单位/轴、序列类型及默认可见性；同样受看板访问保护 |
| `GET /api/v1/nights?start=&end=&cursor=&limit=` | 窗口1—92日，limit1—92；范围内无记录日保留，可选复盘摘要，整夜样本由详情页查询 |
| `GET /api/v1/nights/{D}` | 日期2000—2100；Garmin为空但回退窗口有环境记录时返回environment_only，其他空日404 |
| `GET /api/v1/nights/{D}/timeline?from=&to=&max_points=` | from/to成对且带时区，窗口最多48小时，每序列2—2000显示点上限 |
| `GET /api/v1/environment/timeline?from=&to=&max_points=` | 必填带时区起止，最多48小时；复用同一投影，不依赖Garmin日期存在 |
| GET /api/v1/nights/{D}/analysis | 同快照只读计算当前双源缺项/有效采样覆盖与完整分钟覆盖，模型配置/执行状态独立，并显示已保存报告/证据；不采集、不迁移、不写库、不调用模型 |
| `GET /api/v1/sleep-reviews/{D}` | 只读查询以 D 为截止的 7 日总结及核验或失败状态；刷新不执行重试 |
| `GET /api/v1/status` | 脱敏资源/能力/存储/备份/模型/每日采集/维护状态；`daily`与`maintenance`独立降级，无原始响应下载入口或任务执行副作用 |

列表未给end时使用最近可见睡眠日，无可见睡眠则取配置时区今天与展示起始日的较晚者；未给start时回溯29日，再按展示起点裁剪。旧日详情、夜晚时间轴及分析状态返回404；列表范围或游标完全落在起点前时返回空列表，不生成旧日占位。
HTTP200允许某指标或序列缺失，422表示参数错误，查询失败503仅返回静态错误码。
生成时刻、最近数据时刻、实际观测时刻各自保留，页面不能用查询成功掩盖数据陈旧。

## 页面实现与访问控制

看板页面仅通过`/sleep`或`/sleep/`进入，根路径`/`返回404，不重定向、不要求登录；静态资源和API保留原路径。入口和认证合同见[数据契约](../data-contract.md)，使用步骤见[操作手册](../operations.md#看板入口与持久登录)。

页面由原生HTML/CSS/JavaScript模块组成，随Python包分发，无生产前端构建服务或CDN。
页面协调、同源API请求、格式化工具、时间轴图表、关联记录及分析状态渲染分别负责一层；业务指标公式在服务器端统一计算。
具体目录和依赖方向见[项目架构](../architecture.md)。

默认只允许本机直接访问和本机Host；远程模式须配置独立看板密码，使用加盐PBKDF2哈希并由应用校验HTTP Basic，HTTPS首次认证后支持30天Cookie登录。
远程健康数据请求要求HTTPS；仅直接本机HTTP例外。Caddy保留Authorization，Uvicorn仅信任本机代理头。
页面、静态资源和数据API使用相同保护，不开放跨域，响应no-store，健康数据不落localStorage。
`/health`只返回进程状态，不要求密码；`/docs`始终关闭，debug仅可开放受保护的`/openapi.json`。
真实云端IP证书、受保护外网访问和并发查询已完成首次核验；当前环境曲线包含迁移的USB短采与真实Wi-Fi/TLS上传记录，入库查询已通过。备用移动电源下四通道短时稳定已验，原充电头供电路径异常的具体原因未定；手机首屏和长期资源表现仍须实测，不以首次上线替代持续运行验收。

## 环境数据接入（P3已实现）

当前已接入四环境指标、受限声音事件、分钟详情及设备状态。本机索引启用前完成备份恢复核验，索引已随数据迁入云端；USB短采与真实Wi-Fi/TLS上传记录均可从自定义窗口查询，各自验收证据分别保留。移动电源下短时完整采样已验，查询可用仍不代表整夜完整或长期运行已验收。选型与采购见[硬件方案](hardware.md)。
环境按[数据契约](../data-contract.md#环境采集合同)保留独立来源，以UTC映射关联Garmin，不修改原始Garmin事实。
时间、单位、采样、事件算法、幂等和缺失字段只在数据契约维护；本节规定页面呈现和实施边界。

### 接入层次与访问边界

1. 固件生成分钟汇总和受限事件，独立设备API完成认证、校验和持久化；`EnvironmentViewService`提供P2白名单视图，`environment_dashboard`负责限量、分钟降采样和统一序列投影。
2. `services.views`合并环境与Garmin序列；没有Garmin的日期仍可进入时间轴控件和自定义范围。数据状态页可定位最近环境采集窗口，该窗口不被称为睡眠。环境查询只读，不持有设备令牌、不触发采集。
3. 设备写入口为`POST /api/v1/ingest/environment-batches`，仅对该精确路径窄化现有全局GET/HEAD门禁，并使用专用设备Bearer认证；看板Basic/Cookie访问保护与设备认证独立。不能把设备写入口纳入整站Basic校验，也不能让设备令牌读取健康数据。
4. 显式设备登记创建环境事实表；派生索引通过`environment-index`或`environment-index --rebuild`初始化/重建，先验证备份，`environment-index-verify`使用影子库核验。本机已启用；普通启动和GET不迁移，新机器未启用时明示状态。摄取事务刷新派生数据并提交后才ACK。

### 唯一指标注册表

`domain/metrics.py`为唯一指标清单，受保护的`/api/v1/metrics`供前端`metrics.js`读取；序列选择、图表轴、颜色、图例、提示和URL解析均据此工作。
注册项含稳定`id`、来源、单位、展示名、序列类型、聚合粒度、轴规则、精度、缺失策略和默认可见性。
服务器只返回允许的注册项，前端通过安全DOM呈现；URL只接受已登记ID，未知ID忽略并保留可用项，不执行动态脚本或任意字段访问。
既有四项ID与已有URL兼容；新增硬件可经驱动/配置和注册项扩展，无需重写Garmin页面逻辑。

首批新增温度、相对湿度、光照、相对声音四类轨道：

| 轨道 | 默认显示与提示 | 必须说明的边界 |
| --- | --- | --- |
| 温度 / 相对湿度 | 分钟均值，展开显示min/max、有效/预期读数、设备配置和聚合窗口 | 仅代表传感器摆放处；空窗不延用旧读数 |
| 光照 | 分钟均值及min/max，显示传感器型号和采样覆盖 | 低读数/0不证明绝对无光；本阶段不额外标注自动识别的开灯事件 |
| 相对声音 | `energy_mean_dbfs`和`max_1s_rms_dbfs`，可查看有效音频时长、削波/丢样和配置 | 统一标“相对声音 dBFS”；不显示专业dBA、WHO达标线或跨设备绝对差值 |
| 相对声音事件 | 与时间轴对齐的分钟事件摘要，展开包络、活跃时长、阈值配置及检测/合并/丢弃数 | 合并摘要画区间括号或事件标记，不把包络空白涂成连续声音；不是声源识别或觉醒原因 |

显示降采样仍保留真实窗口与极值，不把一分钟汇总扩展成60个点；提示明确“分钟窗口”，不能伪装瞬时采样时刻。
默认显示环境温度与声音分钟均值；湿度、光照和声音1秒峰值可按图例开启，声音两条类型共用dBFS轴；同指标/类型的多boot序列只生成一个图例开关，数据仍按各自配置和boot分段。URL用hidden/visible记录关闭及默认隐藏项的显式开启，保留既有Garmin ID兼容。注册表请求失败时保留Garmin核心卡并显示可重试状态，不悄悄使用第二套硬编码清单。

### 时间质量、覆盖率和测量断点

- 查询窗口超过8个来源/boot组时，优先展示最新采集结束时刻的8组，同刻按匿名来源/boot引用确定选择，再保留原查询顺序；不用接收时间排序，旧记录补传不挤掉最近采集。页面继续显示组数截断提示，用户可缩小自定义时间窗口查看旧组；未展示不代表上传失败或数据删除，完整规则见[数据契约](../data-contract.md#看板环境投影p3)。
- 每条环境序列显示采集窗口、UTC映射质量、设备接收/上传时刻和配置标识；采集新鲜度与上传新鲜度分别展示，补传不能伪装刚发生的环境变化。
- `unknown`且无UTC的记录仅进入数据状态页统计，不绘制到夜晚；`estimated`显式显示“估计时间”和已知误差，误差未知则明确写未知。`conflict`区间暂停精确叠加并显示原因，不偷偷选一个时刻。
- 按通道显示有效/预期数量；声音另显示PCM采样覆盖、可用1秒窗口覆盖和DMA丢样。局部缺失只影响对应通道；不能以温湿度正常掩盖音频停采。
- 缺口不插值、不补零；没有有效音频或检测器仍在暖机时不显示“0次声音事件”；检测覆盖不足另作提示。全零PCM的数值下限标记与设备掉线分开。零光照按原始量化能力解释。
- 更换传感器、固件处理链、固定增益、算法或摆位时在图上标出配置断点；默认不跨断点连线、比较dBFS涨跌或做混合基线。需要跨配置比较时先具备独立校准依据。
- 设备状态页展示最近已映射采集与最后接收、固件/配置、最后接收的缓存快照、各通道健康、未知时间记录与丢弃计数；不将快照当作当前队列，不把recently_received解释为实时在线。环境读取失败仅影响自己的区域，Garmin内容仍可查看。

### 与Garmin展示衔接及验收

当前Garmin API仍无真实分期区间，继续显示睡眠起止和阶段累计；不能用环境数据补造深睡/浅睡/REM/清醒区间。
环境事件与心率/HRV变化同屏提供观察线索；新增LLM栏目按下节输出受证据限制的解读，不输出确定因果、影响排名、改善幅度或睡眠诊断。
没有Garmin睡眠窗口时沿用现有回退窗口并标明；有环境数据不等于确认用户已经入睡。

实施验收须覆盖：现有四轨与URL交互回归、新指标注册与未知ID处理、通道缺失/全零/部分窗口、配置切换、未知UTC/校时冲突、补传与重复ACK、合并/持续事件，以及设备令牌与UI密码相互隔离。
浏览器测试仅用明确标记的合成数据；真实分钟查询、合成浏览器、云端HTTPS及硬件实际TLS上传结果统一见核验报告。Mac及备用移动电源下四通道短时稳定已验，常驻电源已换用且已有首夜记录，备用电源续航、传感器准确度、连续三晚覆盖和服务器长期运行仍另行验收。

## 每日采集状态（P5已实现）

数据状态页由独立`daily.js`读取`GET /api/v1/status`的`daily`字段。服务端`daily_status`只读运行账本、锁状态与既有SQLite观测，不创建目录、迁移、修复账本、读取密钥或执行采集。日任务的固定安全元数据与逐日期睡眠记录状态分开返回，详细字段以[数据契约](../data-contract.md)为准。

- 显示每天09:00上海时间、配置的回查N日及下一次计划时间；任务时间始终按上海时区解释，避免与其他页面配置时区混淆。页面不探测systemd，安装状态仍显示“未核验”；云端11月18日09:00首次自然执行已有独立证据，见核验报告；页面不把计划时间或一次手工成功当作自然触发已发生。
- 最近运行区分未运行、运行中、完成、部分失败、失败、等待重试与中断；展示任务日、实际睡眠日期范围、阶段、开始/结束时间、允许重试时间、当日尝试次数，以及最近已保存的计划/完成/失败请求项和实际HTTP请求次数。计数不是实时进度，不把未保存的中间进度猜成已完成。
- “本轮请求已完成”与逐日期“已有/缺少/无效/陈旧/请求失败/尚未采集”分别展示。请求成功但空结果仍显示缺少睡眠记录，不立即重复请求；下一日只在配置窗口内补取，页面刷新后读取最新事实。
- 日任务卡的observations仍只表示睡眠观测是否存在，不代表完整性。P4详情独立检查HRV、心率、前日背景和环境整夜四通道；采集后N日检查另有readiness结果，硬件上传独立，报告按自动开关及资格/预算执行，失败不改变采集状态。
- 日任务账本损坏、不可读或旧API缺少`daily`字段时只降级本卡；睡眠观测状态读取失败单独提示“不能据此判断齐全或缺失”。已有Garmin、环境、模型栏目继续可用。
- 前端只渲染固定状态文案、受限日期和计数，不直接显示内部运行ID、路径、来源错误正文或任意标签；安全DOM不执行HTML，不将状态或健康数据写入浏览器持久存储。

卡片没有执行或重试按钮；刷新仅GET，实际执行与显式重试使用受控CLI，操作见[运行手册](../operations.md)。验收覆盖完成但缺少睡眠、次日补取后刷新、失败隔离、旧响应、注入字段、只读访问和窄屏；测试使用合成数据，结果只记在核验报告。

## 自动维护与备份状态（P6已接入）

状态页由独立`maintenance.js`渲染`GET /api/v1/status.maintenance`，复用维护服务的只读投影；字段含义只在[数据契约](../data-contract.md)维护。

- 显示上海时间每日04:00计划与下次计划时刻；页面不探测systemd，仍说明安装未核验。云端11月18日首次自然执行及备份核验已通过，证据见核验报告；页面仅据任务状态展示结果，不凭计划时间推断某次自然触发已发生或一次性维护服务正在常驻。
- 维护运行、完成、部分完成、失败、中断和未执行分别展示，步骤与时间只读取最近已保存记录，不提供猜测的实时进度。
- 本地备份展示受控已核验数量、总量、最近核验时刻、保留预算是否超限，以及保留但不参与自动清理的手动备份。原始观测不在清理范围，最新有效副本继续受保护。
- 磁盘显示系统/数据分区的空闲空间、比例及总体水位，另列数据库、WAL/共享索引和任务元数据大小。只读查询使用有界文件元信息和文件系统容量，不递归扫描或读取备份正文。
- 空间不足时解释大备份与新模型外呼受限；临界时说明环境上传暂不确认入库、Garmin暂停新写入，已有数据仍可读取。不把容量告警解释为已丢失设备数据。
- 离机目标未配置明确显示；已核验的目标副本显示受控份数、字节量及保留预算超限。路径副本已核验不等于已放到另一台设备，离机位置与存储加密仍需单独验收；SSH目标核验和加密传输分别说明，SSH目标也可能指回当前主机，不能据此认定物理离机或长期恢复能力。
- 清单损坏、不可读或旧API缺少维护字段时只降级自己的卡片；固定错误码映射为安全文案，不输出目标路径、主机/账号、内部备份ID、文件摘要、凭据或错误正文。

核验状态表示最近一次检查通过，不保证副本文件现在仍存在。刷新页面不检查文件全文哈希、不联网导出、不删除备份或修改状态；卡片没有执行、恢复或清理按钮。显式维护及临时恢复核验使用CLI，见[运行手册](../operations.md)。合成回归覆盖状态区分、空间保护提示、目标位置说明、只读刷新、注入字段、故障隔离及窄屏布局，结果集中在核验报告。

## 睡眠完整性与LLM栏目（已实现）

夜晚详情由analysis.js读取analysis API，implementation_stage=reports。数据资格/质量、模型配置和报告执行状态分别呈现；显示当前检查时刻、真实睡眠窗口、Garmin缺项、环境阻塞/警告、四通道有效采样覆盖及完整分钟参考。ready只说明数据达到门槛，GET不会自动生成报告。

必需缺项、允许缺采和可选缺项分组；未知分母/来源不补0。“数据缺口与质量提示”默认收拢，标题保留实际条数及“不单独阻塞”；点击标题可展开或收拢全部提示，也支持键盘操作。当前质量结论始终可见。等待数据时直接给出阻塞项数与最多两个相关指标；在“查看完整性检查详情”中可查全部阻塞项、通道采样、检查窗口和策略。时间轴的环境覆盖计数归入通道详情，截断及跨配置提示仍可见。声音分子为完整有效秒，连续受影响分钟跨度只是保守范围。模型配置、等待/生成中、失败/冷却、预算/尝试受限及已生成均有独立文案；未初始化、读取错误和未生成不能混为同一状态。

report.js 和 weekly-report.js 复用 interpretation.js，以纯文本渲染模型判断、佳明与环境解读、可选睡感、可能原因和跨夜对照。旧报告按发布时的结构展示。报告有缺采仍明确质量限制；无分期不补图，dBFS不称dBA。

已发布报告显示生成时间、模型引用和生成时质量。source_changed=true显示来源后来变化，仍保留原报告；null表示当前数据无法比较，不冒充未变化。当前检查失败也尽量保留已保存报告；切日期取消旧请求并校验来源日，错误不串夜或清空其他图表。

“模型配置与请求记录”首先显示本晚报告状态及其生成时间，再单独展示共享账本的最近请求状态、时间和失败原因。共享记录包含探针及各夜晚任务，不用于推断本晚报告是否发布；有效报告存在时仍显示“已生成”，后续或历史失败不撤销成功报告。全局数据状态页只说明共享请求，不凭单次失败显示“报告未发布”，输出校验失败也不称为连接失败。失败审计保留原事实。

历史analysis_summary仍表示上次保存检查、时间、质量与策略；新增report_summary独立显示已生成/未生成/不可读及生成时间，不重算每晚来源指纹。迟到数据可先改变详情，历史检查待显式/每日保存更新；报告本身不会因刷新产生或自动修改。

前端只渲染白名单字段与安全DOM，不展示完整Prompt/模型输入、私有身份/hash、URL/Key或上游错误正文，不把健康数据放浏览器持久存储。未知合同或异常报告结构独立降级；页面无生成/删除按钮。真实与合成界面验收统一见核验报告，规则与发布边界只维护在[LLM方案](llm.md)和[数据契约](../data-contract.md)。
