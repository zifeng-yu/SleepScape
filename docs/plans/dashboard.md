# 看板展示方案

更新：2026-11-11。当前为单人、只读的本地可运行看板；[验收结果](../verification.md)与[运行部署](../operations.md)单独维护。
字段、负荷公式、缺失状态和JSON数据形状以[数据契约](../data-contract.md)为唯一依据。

## 页面职责

| 页面 | 展示与操作 |
| --- | --- |
| 夜晚详情 | 日期选择、上一晚/下一晚、睡眠时长/平均心率/昨夜HRV/昨日负荷，来源及30日基线说明，睡眠窗口、阶段累计、时间轴和事件 |
| 历史记录 | 按7/30个自然日显示摘要及质量状态，保留空日，列排序并进入对应夜晚 |
| 数据状态 | 最近采集、资源成功/失败、暂停时间、数据新鲜度、字段能力、存储计数和本地备份核验时间 |

首屏选择最近有睡眠数据的日期，明确日期及抓取时间；今天已取到的数据仍显示“暂定”。
日期为空时不自动跳过，不把旧夜晚称为今天。页面刷新只查询本地库，不执行Garmin采集。
每张核心卡可展开来源字段、来源日、抓取时间、缺失原因及必要分母；昨日压力/步数与呼吸、评分作为补充。
负荷采用全部运动类型，并关联睡眠日的前一天；列表排序不产生影响因素排名。

## 睡眠与统一时间轴

睡眠窗口显示入睡、醒来和日期；深睡/浅睡/REM/清醒仅显示累计时长，并标明无分期时间线。
当前API没有分期区间，累计条不对应夜间顺序，不能用累计值生成区间。

时间轴默认睡眠起止前后各1小时，共轴展示心率、HRV、SpO2和Body Battery，活动/午睡为独立事件。
没有可信睡眠窗口时回退前日18:00至当日12:00并明确原因，该查询范围不代表推断出的入睡/醒来。
UTC用于对齐，页面按配置时区显示。图表使用实际观测点，缺口不插值、不解释为醒来或离腕；小时血氧与稀疏Body Battery不扩展为连续分钟读数。

支持的交互：

- 光标联动；只在容许时间差内匹配实际样本，提示样本真实时间及距光标时间，无点则显示无观测。
- 框选、平移、Ctrl/Command加滚轮缩放及恢复整夜；键盘支持缩放、平移、Home恢复。
- 整夜、前一日活动、自定义区间；自定义窗口最多48小时。事件可展开摘要并定位时间轴。
- 图例开关；页面、日期、图例和历史7/30日选择写入URL，刷新及浏览器前后退恢复。缩放范围不承诺跨刷新保存。
- 手机响应式排版；普通滚轮/纵向滚动不因默认缩放交互被劫持。真实移动设备验收状态见核验报告。

显示点数受服务器限制。超限序列按时间桶保留有效min/max及真实时刻，附原始/有效/显示点数和桶宽。
稀疏序列直接返回；显示降采样不改变标准化或raw记录，不在空桶生成点，不删除活动事件。

## 只读接口边界

`services.views`通过只读存储查询生成字段白名单，不返回完整raw、owner、GPS、凭据或文件绝对路径。

| 路由 | 查询限制 |
| --- | --- |
| `GET /api/v1/nights?start=&end=&cursor=&limit=` | 窗口1—92日，limit1—92；不返回整夜样本，范围内无记录日保留 |
| `GET /api/v1/nights/{D}` | 日期2000—2100；返回单日视图，无该来源日记录时404 |
| `GET /api/v1/nights/{D}/timeline?from=&to=&max_points=` | from/to成对且带时区，窗口最多48小时，每序列2—2000显示点上限 |
| `GET /api/v1/status` | 脱敏资源/能力/存储/备份状态，无原始响应下载入口 |

列表未给end时使用最近睡眠日，无睡眠则取配置时区今天；未给start时回溯29日。
HTTP200允许某指标或序列缺失，422表示参数错误，查询失败503仅返回静态错误码。
生成时刻、最近数据时刻、实际观测时刻各自保留，页面不能用查询成功掩盖数据陈旧。

## 页面实现与访问控制

页面由原生HTML/CSS/JavaScript模块组成，随Python包分发，无生产前端构建服务或CDN。
页面协调、同源API请求、格式化工具和时间轴图表分别负责一层；业务指标公式在服务器端统一计算。
具体目录和依赖方向见[项目架构](../architecture.md)。

默认只允许本机直接访问和本机Host；远程模式须配置独立看板密码，使用加盐PBKDF2哈希并由应用校验HTTP Basic。
远程健康数据请求要求HTTPS；仅直接本机HTTP例外。Caddy保留Authorization，Uvicorn仅信任本机代理头。
页面、静态资源和数据API使用相同保护，不开放跨域，响应no-store，健康数据不落localStorage。
`/health`只返回进程状态，不要求密码；`/docs`始终关闭，debug仅可开放受保护的`/openapi.json`。
真实云端证书、外网访问及2C2G性能仍须部署验收，不因本机测试通过而宣称已上线。

## 环境数据接入（采集接口已实现，页面待接入）

当前固件、独立写入路由、环境存储和合同回归已建立；UTC查询映射、页面环境轨道及真实硬件曲线仍待实现与实物验收。选型与采购见[硬件方案](hardware.md)。
后续按[数据契约的环境采集合同](../data-contract.md#环境采集合同)增加独立来源，以UTC映射关联Garmin，不修改原始Garmin事实。
时间、单位、采样、事件算法、幂等和缺失字段只在数据契约维护；本节规定页面呈现和实施边界。

### 接入层次与访问边界

1. 固件生成分钟汇总和受限事件，独立设备API完成认证、校验和持久化；服务端环境查询适配器向视图层提供白名单记录。
2. `services.views`合并可展示的环境与Garmin序列；页面仍只调用只读API，不持有设备令牌、不触发采集、不写设备数据。
3. 已实现写入口为`POST /api/v1/ingest/environment-batches`，仅对该精确路径窄化现有全局GET/HEAD门禁，并使用专用设备Bearer认证；看板HTTP Basic保护不变。不能把设备写入口纳入整站Basic校验，也不能让设备令牌读取健康数据。
4. 显式设备登记创建环境表、时间锚点、配置和接收审计；已有Garmin事实保持独立。普通看板启动不迁移库。软件合同及存储/接口验证已建立，下一步接真实硬件后扩展页面。

### 从固定四轨改为指标注册表

当前心率、HRV、SpO2、Body Battery四轨及图例/URL状态白名单是既有实现边界，尚不能仅靠增加一条环境JSON就自动显示。
接入时将序列选择、图表轴、颜色、图例、提示和URL图例解析统一改为服务端/前端共享约定的指标注册表，避免各处复制指标列表。
注册项至少含稳定`metric_id`、来源、单位、展示名、允许的聚合类型、采样粒度、轴规则、提示格式、缺失策略和可见性。
服务器只返回允许的注册项，前端通过安全DOM呈现；URL只接受已登记ID，未知ID忽略并保留可用项，不执行动态脚本或任意字段访问。
既有四项ID与已有URL兼容；新增硬件可经驱动/配置和注册项扩展，无需重写Garmin页面逻辑。

首批新增温度、相对湿度、光照、相对声音四类轨道：

| 轨道 | 默认显示与提示 | 必须说明的边界 |
| --- | --- | --- |
| 温度 / 相对湿度 | 分钟均值，展开显示min/max、有效/预期读数、设备配置和聚合窗口 | 仅代表传感器摆放处；空窗不延用旧读数 |
| 光照 | 分钟均值及min/max，显示传感器型号和采样覆盖 | 低读数/0不证明绝对无光；本阶段不额外标注自动识别的开灯事件 |
| 相对声音 | `energy_mean_dbfs`和`max_1s_rms_dbfs`，可查看有效音频时长、削波/丢样和配置 | 统一标“相对声音 dBFS”；不显示专业dBA、WHO达标线或跨设备绝对差值 |
| 相对声音事件 | 与时间轴对齐的分钟事件摘要，展开包络、活跃时长、阈值配置及检测/合并/丢弃数 | 合并摘要画区间括号或事件标记，不把包络空白涂成连续声音；不是声源识别或觉醒原因 |

显示降采样仍保留真实窗口与极值，不把一分钟汇总扩展成60个点；提示明确“分钟窗口”，不能伪装瞬时采样时刻。
默认减少同时展开的轨道，可按图例选择；环境序列与身体指标用同一横轴，各自保留单位和纵轴，不将不同单位合成一个分数。

### 时间质量、覆盖率和测量断点

- 每条环境序列显示采集窗口、UTC映射质量、设备接收/上传时刻和配置标识；采集新鲜度与上传新鲜度分别展示，补传不能伪装刚发生的环境变化。
- `unknown`且无UTC的记录仅进入数据状态页统计，不绘制到夜晚；`estimated`显式显示“估计时间”和已知误差，误差未知则明确写未知。`conflict`区间暂停精确叠加并显示原因，不偷偷选一个时刻。
- 按通道显示有效/预期数量；声音另显示PCM采样覆盖、可用1秒窗口覆盖和DMA丢样。局部缺失只影响对应通道；不能以温湿度正常掩盖音频停采。
- 缺口不插值、不补零；没有有效音频或检测器仍在暖机时不显示“0次声音事件”；检测覆盖不足另作提示。全零PCM的数值下限标记与设备掉线分开。零光照按原始量化能力解释。
- 更换传感器、固件处理链、固定增益、算法或摆位时在图上标出配置断点；默认不跨断点连线、比较dBFS涨跌或做混合基线。需要跨配置比较时先具备独立校准依据。
- 设备状态页增加最近成功采集/上传、固件与配置、缓存积压、补传状态、各通道健康、未知时间记录数及丢弃计数；展示的是运行证据，不宣称硬件已经完成医学或专业声学校准。

### 与Garmin展示衔接及验收

当前Garmin API仍无真实分期区间，继续显示睡眠起止和阶段累计；不能用环境数据补造深睡/浅睡/REM/清醒区间。
环境事件与心率/HRV变化同屏只提供观察线索，页面不输出影响排名、原因、改善幅度或睡眠诊断。
没有Garmin睡眠窗口时沿用现有回退窗口并标明；有环境数据不等于确认用户已经入睡。

实施验收须覆盖：现有四轨与URL交互回归、新指标注册与未知ID处理、通道缺失/全零/部分窗口、配置切换、未知UTC/校时冲突、补传与重复ACK、合并/持续事件，以及设备令牌与UI密码相互隔离。
浏览器测试仅用明确标记的合成数据；真机数据对齐、2C2G容量和云端HTTPS另行验收，未执行前不标为完成。
