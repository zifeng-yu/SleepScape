## 后续执行顺序

1. **确认常驻稳定USB供电。** 原充电头供电路径曾有I²C异常，原因未定。原位换合适电源、保持传感器线不动，以新boot及私有记录核验。先观察至少两个上传周期，再验连续三晚与白天运行。
2. **验证采集恢复并观察自然报告稳定性。** 稳定供电后在白天先做短时断网恢复，核对同一boot的分钟序号、补传及丢失计数，再进行48小时离线补传和受控掉电验收。连续记录各通道覆盖、声音缺秒和光照总线错误。继续观察缺Garmin次日补取、迟传达到门槛后的自然发布、已发布夜晚跳过及报告正文与证据的一致性。目标机停机补跑与超时恢复另验。
3. **确定离机备份位置并验证恢复。** 选择真实另一机器/存储，配置已实现路径或SSH导出，验证同批SQLite与模型/每日/冷却账本恢复。加密传输不等于目标磁盘已加密；目标未确定前保持未配置。
4. **证书自然续期及长期运行验收。** 与供电验收并行，在当前证书到期前观察序列号和有效期变化、可信HTTPS及设备新批次。第7/30天复核磁盘、内存、日志、数据库/报告/备份增长及并发查询。
5. **核验新完整性策略下的报告任务自然执行。** 光照规则已部署，指定夜晚已保存复查结果，所选截止日的复盘已补生成。后续 09:00 任务分别核对逐夜资格、实际 7 日窗口、重试与预算。持续抽查两份报告正文与证据，完成真机手机验收。 [光照规则核验](../verification.md#光照完整性规则核验2026-11-23)

6. **设备接入 USB 时升级并验收回听。** 声音事件回听的云端已就绪。待设备 USB 接入后按[升级步骤](../operations.md#声音事件回听升级)普通刷入 0.4.0，核对新 profile 与四通道，实测夜间事件、次日窗口裁剪及看板回听。
